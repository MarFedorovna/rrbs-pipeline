# Предполагаемые системные требования

Для быстрого анализа четырёх RRBS-образцов рекомендуется **32 vCPU, не менее 128 ГБ RAM, около 300 ГБ свободного NVMe/SSD и Ubuntu 22.04 или 24.04 x86_64**. Это предварительная оценка под текущую реализацию, а не измеренный минимум или гарантия времени выполнения.

| Ресурс | Экономная конфигурация | Рекомендуемая конфигурация |
|---|---|---|
| CPU | 16 vCPU | 32 vCPU |
| RAM | 64 ГБ | от 128 ГБ |
| Свободный диск | 200–300 ГБ SSD | 300 ГБ NVMe/SSD |
| ОС | Linux x86_64 | Ubuntu 22.04 / 24.04 x86_64 |
| Сеть | Доступ по HTTPS к ENA, UCSC и каналам Conda | Желательно устойчивое соединение от 100 Мбит/с |

Bismark/Bowtie2 и methylKit в этой реализации выполняют вычисления на CPU. Быстродействие определяется процессором, параллелизмом, RAM и диском. Видеопамять не заменяет RAM. Количество vCPU не обязательно совпадает с числом физических ядер.

## Использование ресурсов

Workflow обрабатывает образцы параллельно. На alignment одного образца резервируются 8 vCPU и 24 ГБ RAM. На 32 vCPU и 128 ГБ могут одновременно идти четыре выравнивания, если другие задачи не заняли ресурсы. Внутренний параллелизм Bismark учитывается отдельно; дополнительные процессы не запускаются без учёта общего бюджета. Экстрактору резервируются примерно три CPU на одну parallel instance. Индексатор запускает две strand-specific задачи, что также учтено.

`profiles/cpu32` задаёт общий бюджет 32 vCPU и 112 000 MB RAM, оставляя запас для ОС. Сервер с большей RAM может использовать этот профиль без изменений. `profiles/cpu16` рассчитан на 16 vCPU / 64 ГБ. Дополнительный профиль `profiles/cpu8` поддерживает ограниченный CPU-бюджет при RAM от 128 ГБ.

Исходные FASTQ занимают около 9,75 ГБ в сжатом виде. Дополнительно нужны полный hg38, бисульфитные индексы, обрезанные чтения, BAM и промежуточные файлы methylation extraction. Рекомендация 300 ГБ включает запас; фактический размер полного результата ещё не измерен.

Увеличение CPU с 32 до 64 не гарантирует двукратного ускорения. Текущий профиль использует до 32 vCPU; дополнительным ядрам требуется отдельная настройка и проверка масштабирования. Для более крупной серии размер машины следует оценить повторно.

## Как уточнить время

1. Установите окружение и выполните синтетический smoke test.
2. Подготовьте данные: `bash scripts/prepare_data.sh`.
3. Выполните один реальный образец до Bismark report командой из README.
4. Проверьте mapping efficiency и M-bias, время и пиковую RAM в benchmarks. При необходимости измените clipping и повторите extraction.
5. Запустите весь набор и измерьте отдельное время methylKit. Время статистики нельзя вывести только из скорости alignment.

Конкретное время полного анализа и стоимость аренды в системные требования не заложены. Индексы и входные данные кешируются. Перед остановкой машины сохраните нужные результаты на постоянном диске; свойства временного диска определяются выбранным тарифом.

Основание расчётов: [требования Bismark](https://felixkrueger.github.io/Bismark/installation/), [параллелизм](https://felixkrueger.github.io/Bismark/options/alignment/), [исходный код Bismark 0.25.1](https://github.com/FelixKrueger/Bismark/tree/v0.25.1). Размер сервера — инженерная оценка для текущего workflow, не benchmark производителя.
